## 1. 서비스 개요

### 1-1. 한 줄 정의

> **비버가 궁금할 때, 물어보면 답이 나오는 한국어 사이트**

사용자가 자연어로 질문하면 논문 근거가 붙은 답변을 제공하고, 실제 영상으로 확인까지 할 수 있는 비버 전문 서비스.

### 1-2. 문제 정의

| 문제 | 현황 |
|---|---|
| 한국어 비버 자료 부재 | 국내 서식종이 아니어서 국내 연구·자료가 사실상 없음 |
| 검색해도 한 줄에서 끝남 | "비버 이빨 왜 주황색" → "철 때문" 이상의 정보가 없음 |
| 자료가 영어권에 편중 | 신뢰할 수 있는 정보가 전부 영어 논문에 있음 |
| 지식과 영상이 분리 | "왜 그런지" 읽는 곳과 "실제로 그런지" 보는 곳이 따로 있음 |

**핵심 문제**
비버가 궁금한 한국인이 답을 찾을 곳이 없음.

### 1-3. 타깃 사용자

| 구분 | 설명 | 유입 경로 |
|---|---|---|
| 1차 | SNS에서 비버를 접하고 궁금해진 사람 | 검색 유입 |
| 2차 | 비버를 이미 좋아하는 사람 | 커뮤니티·SNS 공유 |
| 3차 | 동물·생태에 관심 있는 사람 | 검색 유입 |

**로그인 없음.** 진입장벽 0이 서비스 정체성.

### 1-4. 차별점

| 비교 대상 | 비버마을의 차이 |
|---|---|
| 나무위키·위키백과 | 논문 출처를 명시하고, 실제 영상을 함께 제공 |
| 유튜브 | 큐레이션되어 있고, 왜 그런 행동을 하는지 설명이 붙음 |
| 일반 AI 챗봇 | **검증된 자료 안에서만 답함.** 출처가 항상 따라붙음 |
| 해외 비버 사이트 | 한국어로 되어 있음 |

**"물어보면 답이 나오는데, 그 답에 논문이 붙어 있는 것"** 이 핵심 차별점.

## 2. 컨셉 및 톤앤매너

### 2-1. 세계관: 마을

```
비버마을
├─ 마을 도서관    비버 궁금증 아카이브 (핵심 콘텐츠)
├─ 오늘의 비버    큐레이션된 비버 영상
├─ 마을회관       익명 한 줄 반응
└─ 마을 소개      사이트 소개 및 운영 원칙
```

### 2-2. 톤

**"친구가 알려주는 톤."** 백과사전체 지양. 단, 수치와 논문 결론은 엄밀하게.

| 지향 | 지양 |
|---|---|
| "알고 보니 그냥 색소가 아니었습니다" | "비버의 절치는 철 이온이 침착되어 있으며" |
| 궁금증을 먼저 던지고 답하는 구성 | 분류학적 정보부터 나열하는 구성 |

### 2-3. 비주얼 컨셉

2000년대 개인 홈페이지 감성을 의도적으로 차용. 세련됨보다 **애정이 느껴지는 촌스러움**을 지향.

| 요소 | 설명 | 차수 |
|---|---|---|
| 커서 추적 비버 | 마우스를 뒤뚱거리며 따라오는 비버 | 1차 |
| 양옆 여백 비버 사진 | 흐리게 처리한 배경 이미지 | 1차 |
| 방문자 카운터 | "당신은 n번째 마을 방문객입니다" | 1차 |
| 물방울 클릭 효과 | 클릭 시 물방울이 튀는 연출 | 2차 |
| 스크롤 패럴랙스 | 배경 사진이 본문보다 느리게 따라옴 | 2차 |
| 배경음악 자동재생 | **미채택** — 브라우저 차단 + 이탈률 | 제외 |

## 3. 첫 화면 설계

### 3-1. 구조

```
┌──────┬────────────────────────────────┬──────┐
│      │        🦫 비버마을              │      │
│ 비버 │   비버에 대해 궁금한 게         │ 비버 │
│ 사진 │      있으신가요?                │ 사진 │
│      │  ┌──────────────────┬────┐     │      │
│ (흐림)│  │ 비버는 왜 귀여워? │검색│     │(흐림)│
│      │  └──────────────────┴────┘     │      │
│      │   [추천 질문 칩 3개]            │      │
│      │  ─────────────────────────      │      │
│      │   오늘의 비버 (영상)            │      │
│      │   당신은 1,247번째 방문객        │      │
└──────┴────────────────────────────────┴──────┘
```

### 3-2. 설계 의도

| 요소 | 의도 |
|---|---|
| 검색창을 중앙 최상단에 배치 | 목록을 둘러보는 사이트가 아니라 **물어보는 사이트**임을 첫눈에 전달 |
| 추천 질문 칩 | 빈 검색창 앞에서 막히는 것을 방지. 무엇을 물어도 되는지 예시 제공 |
| 영상 배치 | 답을 안 찾는 방문자도 머물게 하는 유입 장치 |
| 방문자 카운터 | 옛날 감성 연출 + "얼마나 알렸는가"의 지표 |
| 양옆 배경 사진 | 첫인상에서 "비버 세상"임을 즉시 전달 |

### 3-3. 배경 이미지 요건

| 항목 | 요건 |
|---|---|
| 출처 | **Wikimedia Commons 등 CC 라이선스 이미지만 사용.** SNS 이미지 사용 금지 |
| 화질 | 흐림 처리되는 장식이므로 저해상도로 충분 |
| 로딩 | `loading="lazy"` 적용. 검색창 렌더링을 지연시키지 않을 것 |
| 반응형 | 모바일에서는 좌우 여백이 없으므로 **상단 가로 스트립 1개로 대체** |
| 접근성 | 장식 이미지이므로 `alt=""` 처리 |

## 4. 핵심 기능

### 4-1. 마을 도서관 (핵심 콘텐츠)

**콘텐츠 1건의 구조**

```
[질문]  비버 이빨은 왜 주황색일까?
[답]    본문 3~5문단
[근거]  논문 출처 (저자·연도·링크)
[영상]  해당 내용이 확인되는 유튜브 영상
[반응]  익명 한 줄 코멘트
```

**분류 체계**

| 카테고리 | 예시 질문 |
|---|---|
| 몸 | 이빨이 왜 주황색인가 / 꼬리는 왜 납작한가 / 왜 뒤뚱거리는가 |
| 행동 | 댐은 왜 짓는가 / 어떻게 나무를 쓰러뜨리는가 / 꼬리로 물을 치는 이유 |
| 생태 | 비버 댐이 생태계에 미치는 영향 / 겨울을 어떻게 나는가 |
| 사람과의 관계 | 왜 구조되는가 / 사람을 따르는 이유 / 복원 사업 사례 |

논문 1편에서 여러 질문을 도출하여 콘텐츠 생산 효율을 확보함.

### 4-2. 의미 검색 (2차 핵심 기능)

**동작 흐름**

```
사용자 질문 입력
   ↓ 임베딩 변환
pgvector 유사도 검색 → 관련 콘텐츠 상위 3건
   ↓
검색된 콘텐츠 내용만으로 답변 구성
   ↓
답변 + 참조한 글 링크 + 논문 출처 표시
```

**키워드 검색이 아닌 의미 검색을 채택하는 이유**
"비버는 왜 이렇게 귀여워?"라는 질문에는 매칭될 키워드가 없음.
의미 기반 검색이어야 "왜 뒤뚱거리는가", "꼬리는 왜 납작한가" 같은 관련 콘텐츠로 연결됨.

**절대 원칙 — 답변 생성 범위 제한**

| 방식 | 채택 여부 | 사유 |
|---|---|---|
| 검색된 자사 콘텐츠 내에서만 답변 구성 | **채택** | 모든 답변에 검증된 근거가 따라붙음 |
| 모델의 일반 지식으로 답변 생성 | **미채택** | 출처 없는 정보가 논문 기반 사이트의 신뢰를 무너뜨림 |

프롬프트에 **"제공된 자료에 없는 내용은 답하지 말 것"** 을 명시적으로 강제함.

**검색 실패 시 처리**

```
"아직 마을 도서관에 그 답은 없어요.
 궁금하신 걸 남겨주시면 조사해볼게요."   → 질문을 DB에 수집
```

없는 내용을 억지로 연결하지 않음. 수집된 질문은 **다음 콘텐츠 소재 목록**이 됨.
이로써 소재 고갈 문제를 사용자 유입으로 해결하는 구조가 성립함.

### 4-3. 오늘의 비버

| 항목 | 내용 |
|---|---|
| 수집 방식 | YouTube Data API `playlistItems.list` |
| 대상 | 사전 선별한 비버 전문 채널 3~5개 |
| 주기 | 1일 1회 (Vercel Cron) |
| 저장 | 영상 ID·제목·썸네일·게시일만 저장 |

**키워드 검색 미사용 사유**
`beaver`는 영어권 성적 속어이며, 무관한 유아 교육 채널이 상위 노출됨.
**채널 단위 큐레이션이 선택이 아니라 필수임.**

### 4-4. 마을회관 (익명 반응)

| 항목 | 정책 |
|---|---|
| 인증 | 없음 |
| 글자 수 | 최대 30자 |
| 작성 제한 | IP 기준 1분 3건 |
| 링크 허용 | instagram.com, youtube.com, youtu.be 만 |
| 검수 | 초기 수동 승인 |

**30자 제한의 설계 의도**
스팸 방지인 동시에 분위기 설계 장치. 짧은 감탄만 남게 되어 긍정적 공간이 형성됨.

## 5. 정보 구조 및 URL 설계

```
/                          대문 (검색창 중심)
/search?q=                 검색 결과
/library                   마을 도서관 목록
/library/[category]        카테고리별 목록
/library/[category]/[slug] 개별 콘텐츠
/videos                    오늘의 비버 목록
/guestbook                 마을회관
/about                     마을 소개
```

**SEO 고려사항**
- 검색 유입이 유일한 성장 채널이므로 콘텐츠 페이지는 **SSG로 정적 생성**
- slug는 영문, 제목은 질문형 한글 (예: `/library/body/orange-teeth`)
- `title`, `description`, Open Graph 태그 필수
- 구조화 데이터 `FAQPage`(JSON-LD) 적용 — 질문형 콘텐츠와 정확히 부합함
- 검색 결과 페이지(`/search`)는 `noindex` 처리

## 6. 데이터 모델

### 6-1. 테이블 구조

```sql
-- 벡터 검색 확장
create extension if not exists vector;

-- 도서관 콘텐츠
create table articles (
  id            uuid primary key default gen_random_uuid(),
  slug          text unique not null,
  category      text not null,                 -- body | behavior | ecology | human
  question      text not null,                 -- 질문 (제목 역할)
  content       text not null,                 -- 본문 (마크다운)
  summary       text,                          -- 검색 답변 구성용 요약
  source_title  text,
  source_author text,
  source_year   int,
  source_url    text,
  video_id      text,
  embedding     vector(1536),                  -- 의미 검색용
  published     boolean default false,
  created_at    timestamptz default now()
);

-- 큐레이션 영상
create table videos (
  id           uuid primary key default gen_random_uuid(),
  youtube_id   text unique not null,
  title        text not null,
  thumbnail    text,
  channel_name text,
  published_at timestamptz,
  created_at   timestamptz default now()
);

-- 익명 반응
create table comments (
  id          uuid primary key default gen_random_uuid(),
  target_type text not null,                   -- article | video | guestbook
  target_id   uuid,
  content     text not null check (char_length(content) <= 30),
  approved    boolean default false,
  created_at  timestamptz default now()
);

-- 답을 찾지 못한 질문 (콘텐츠 소재 풀)
create table unanswered_questions (
  id         uuid primary key default gen_random_uuid(),
  question   text not null,
  hit_count  int default 1,                    -- 같은 질문 반복 시 누적
  resolved   boolean default false,            -- 콘텐츠로 작성 완료 여부
  created_at timestamptz default now()
);

-- 방문자 카운터
create table visitors (
  id    int primary key default 1,
  count bigint default 0
);

-- 유사도 검색 함수
create or replace function match_articles(
  query_embedding vector(1536),
  match_count int default 3
)
returns table (id uuid, slug text, question text, summary text, similarity float)
language sql stable
as $$
  select a.id, a.slug, a.question, a.summary,
         1 - (a.embedding <=> query_embedding) as similarity
  from articles a
  where a.published = true and a.embedding is not null
  order by a.embedding <=> query_embedding
  limit match_count;
$$;
```

**설계 의도**
- `user_id` 없음 — 익명 서비스이므로 사용자 개념 자체가 없음
- 미디어 파일 미저장 — 전부 임베드 방식이므로 스토리지 부담 없음
- `unanswered_questions.hit_count` — 여러 번 들어온 질문일수록 우선 작성
- `summary` 분리 — 검색 답변 구성 시 본문 전체가 아닌 요약만 넘겨 토큰 절약

### 6-2. RLS 정책

| 테이블 | 읽기 | 쓰기 |
|---|---|---|
| articles | 전체 (`published = true`만) | 관리자만 |
| videos | 전체 | 서버(서비스 키)만 |
| comments | 전체 (`approved = true`만) | 전체 (익명 삽입 허용) |
| unanswered_questions | 관리자만 | 서버만 |
| visitors | 전체 | 서버만 |

**핵심 포인트**
`comments`는 **익명 삽입은 허용하되 조회는 승인된 것만** 노출.
이 비대칭 정책이 로그인 없는 서비스의 안전장치가 됨.

## 7. 기술 스택

| 영역 | 기술 | 선정 이유 |
|---|---|---|
| 프레임워크 | Next.js 15 (App Router) | SSG/ISR로 SEO 확보. 검색 유입이 핵심 채널 |
| 언어 | TypeScript | 타입 안정성 |
| 스타일 | Tailwind CSS | 빠른 시안 반영 |
| DB·벡터 | Supabase (PostgreSQL + pgvector) | 벡터 검색 내장. 별도 벡터 DB 불필요 |
| 배포 | Vercel | Cron 포함, Hobby 플랜 무료 |
| 영상 | YouTube Data API v3 | 일 10,000 unit 무료 |
| 임베드 | Instagram oEmbed | 2026년 6월부터 토큰·앱 심사 없이 사용 가능 |
| 임베딩·답변 | LLM API | **2차부터 도입** |

### 비용 계획

| 차수 | 비용 | 내역 |
|---|---|---|
| 1차 | **0원** | 전부 무료 티어 |
| 2차 | **월 1,000원 내외** | 임베딩 위주. 생성보다 저렴 |
| 3차 | 월 5,000원 내외 | 댓글 검수 추가 시 |

임베딩은 콘텐츠 작성 시 1회만 생성하면 되고, 질문 임베딩은 단가가 낮아 부담이 없음.

## 8. 콘텐츠 운영 원칙

### 8-1. 논문 활용 원칙

| 허용 | 금지 |
|---|---|
| 직접 소화하여 재작성한 설명 | 원문 번역본 전문 게재 |
| 수치를 인용하며 출처 명시 | 논문 그림·표 그대로 게재 |
| 오픈액세스 논문 우선 활용 | 유료 논문 PDF 공유 |
| 저자·연도·DOI 명시 후 원문 링크 | 출처 없이 내용만 게재 |

**원칙: "번역"이 아니라 "해설"**

### 8-2. 정확도 관리

인과와 상관을 혼동하지 말 것.

```
원문: "associated with a 30% reduction"
오역: "30% 감소시켰다"           (인과)
정역: "30% 감소와 연관을 보였다"  (상관)
```

핵심 인용 문장은 원문과 대조 후 게재.

### 8-3. 이미지 저작권

| 용도 | 출처 |
|---|---|
| 배경 장식 이미지 | Wikimedia Commons 등 CC 라이선스 |
| 콘텐츠 내 영상 | 유튜브 공식 임베드 |
| 사용자 공유 링크 | Instagram oEmbed (원본 서버가 제공) |

**이미지 파일을 직접 복제·저장하지 않는 것이 원칙.** 임베드는 원 저작자 표기가 유지됨.

### 8-4. 집필 워크플로

```
질문 선택 (unanswered_questions 우선)
   ↓
관련 논문 검색 (오픈액세스 우선)
   ↓
Abstract로 활용 여부 판단
   ↓
Results·Discussion 집중 확인
   ↓
LLM 초벌 정리 (선택)
   ↓
원문 대조 검증
   ↓
본인 관점을 더해 재작성
   ↓
영상 매칭 → 임베딩 생성 → 게시
```

**LLM은 집필 보조 도구.** 자동 생성·자동 게시는 채택하지 않음.

## 9. 마일스톤

### 1차 — 마을 개장 (2주)

| 범위 | 산출물 |
|---|---|
| 첫 화면 | 검색창 중심 레이아웃, 배경 이미지, 방문자 카운터 |
| 도서관 | 콘텐츠 10편, 목록·상세 화면, 카테고리 필터 |
| 검색 | **키워드 기반 단순 검색** (의미 검색은 2차) |
| 오늘의 비버 | 채널 3~5개 수집, 목록 화면 |
| 마을회관 | 익명 반응 작성·표시 |
| 감성 요소 | 커서 비버 |
| 인프라 | Supabase 스키마·RLS, Vercel 배포·Cron |

**완료 기준: 검색으로 들어온 사람이 답을 얻고 반응을 남기고 갈 수 있는 상태**

1차에서 의미 검색을 넣지 않는 이유: 콘텐츠가 10편 수준에서는 키워드 검색으로도 충분하며, 검색 대상이 부족한 상태에서 벡터 검색의 효과가 드러나지 않음.

### 2차 — 물어보는 마을 (2주)

- 콘텐츠 30편까지 확충
- **의미 검색 도입** (pgvector + 임베딩)
- **자료 범위 내 답변 생성**
- 미답변 질문 수집 기능
- 물방울 효과, 스크롤 패럴랙스
- OG 이미지 자동 생성

### 3차 — 자동화 (필요 시)

- LLM 기반 댓글 검수
- 링크 적합성 자동 판별
- **선행 조건: 수동 승인이 감당되지 않는 수준의 유입 발생**

## 10. 비기능 요건

| 항목 | 요건 |
|---|---|
| SEO | 콘텐츠 페이지 SSG, 메타·OG 태그, FAQPage 구조화 데이터 |
| 성능 | LCP 2.5초 이내. 배경 이미지가 검색창 렌더링을 막지 않을 것 |
| 반응형 | 모바일 우선. 좌우 배경은 모바일에서 상단 스트립으로 대체 |
| 접근성 | 장식 이미지 `alt=""`, 커서 효과에 `prefers-reduced-motion` 대응 |
| 스팸 방어 | 글자 수 제한, IP 레이트 리밋, 도메인 화이트리스트, 수동 승인 |
| 검색 남용 방어 | 2차 도입 시 IP 기준 검색 횟수 제한 (임베딩 비용 보호) |

## 11. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 연재 부담으로 콘텐츠 중단 | 사이트 방치 | 영상·게시판은 자동 순환되므로 도서관이 멈춰도 사이트는 유지됨 |
| 검색 결과가 빈약함 | 첫 인상 훼손 | 콘텐츠 10편 미만 상태로 오픈하지 않음. 추천 질문 칩으로 유도 |
| LLM이 없는 내용을 지어냄 | 신뢰도 붕괴 | 프롬프트에서 자료 범위 밖 답변 금지를 강제. 미검색 시 솔직히 안내 |
| 익명 게시판 악용 | 분위기 훼손 | 30자 제한 + 화이트리스트 + 수동 승인 |
| 논문 내용 오독 | 신뢰도 손상 | 원문 대조 필수, 출처 상시 노출로 검증 가능하게 함 |
| 배경 이미지 저작권 | 법적 문제 | CC 라이선스 이미지만 사용. SNS 이미지 사용 금지 |
| 검색 API 비용 폭증 | 예산 초과 | IP 기준 레이트 리밋. 임베딩 결과 캐싱 |
