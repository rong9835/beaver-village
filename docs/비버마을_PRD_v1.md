| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |

## 4. 사용자 플로우

### 4-1. 주 플로우 — 검색 유입

```
구글 검색 "비버 이빨 주황색"
   ↓
콘텐츠 상세 페이지 직접 진입 (SSG)
   ↓
답 읽음 → 논문 출처 확인 → 관련 영상 시청
   ↓
[분기 A] 반응 남기고 이탈
[분기 B] 다른 질문 클릭 → 도서관 탐색
[분기 C] 대문 이동 → 다른 궁금증 검색
```

**설계 포인트**
대문이 아니라 **상세 페이지가 실질적 첫 화면**이 됨.
따라서 상세 페이지에 사이트 정체성과 다음 행동 유도가 반드시 포함되어야 함.

### 4-2. 보조 플로우 — 대문 진입

```
대문 진입
   ↓
[분기 A] 검색어 입력 → 검색 결과 → 상세
[분기 B] 추천 질문 칩 클릭 → 상세 직행
[분기 C] 오늘의 비버 시청 → 반응 작성
```

## 5. 화면별 상세 명세

### F-01. 대문 (`/`)

**렌더링 방식**: ISR (`revalidate: 3600`)

| 영역 | 구성 요소 | 요구사항 |
|---|---|---|
| 좌우 여백 | 비버 배경 이미지 각 3장 | CC 라이선스, 흐림 처리, `loading="lazy"`, `alt=""` |
| 헤더 | 로고 + 사이트명 | 클릭 시 대문 이동 |
| 히어로 | "비버에 대해 궁금한 게 있으신가요?" | 18px 이상, 화면 최상단 노출 |
| 검색창 | 입력 필드 + 검색 버튼 | placeholder에 실제 질문 예시 사용 |
| 추천 칩 | 질문 3개 | 클릭 시 해당 콘텐츠로 직행 (검색 거치지 않음) |
| 오늘의 비버 | 최신 영상 1건 | 썸네일 우선 표시, 클릭 시 재생 |
| 카운터 | "당신은 n번째 마을 방문객입니다" | 숫자에 `toLocaleString()` 적용 |
| 푸터 | 마을 소개 링크, 운영 원칙 링크 | — |

**반응형**
- 데스크톱(≥1024px): 3단 구성 (배경 / 본문 / 배경)
- 태블릿(768~1023px): 좌우 배경 각 1장으로 축소
- 모바일(<768px): **좌우 배경 제거, 상단 가로 스트립 1장으로 대체**

**상태 정의**

| 상태 | 처리 |
|---|---|
| 영상 없음 | 오늘의 비버 섹션 자체를 숨김 (빈 박스 노출 금지) |
| 카운터 조회 실패 | 카운터 문구만 숨김. 화면 전체는 정상 렌더링 |

---

### F-02. 검색 결과 (`/search?q=`)

**렌더링 방식**: CSR (`noindex` 처리)

| 요구사항 | 내용 |
|---|---|
| 검색 대상 | `articles.question`, `articles.content` |
| 검색 방식 | PostgreSQL `ilike` 부분 일치 (1차 한정) |
| 정렬 | 질문 일치 우선 → 본문 일치 |
| 결과 표시 | 질문, 요약 2줄, 카테고리 배지 |
| 결과 없음 | "아직 그 답은 준비 중이에요" + 전체 목록 유도 |
| 입력 검증 | 공백만 입력 시 검색 미실행, 인라인 안내 표시 |

**중요**
결과 없음 화면은 **막다른 길이 되면 안 됨.** 반드시 도서관 목록 또는 추천 질문으로 연결.

---

### F-03. 마을 도서관 목록 (`/library`, `/library/[category]`)

**렌더링 방식**: SSG

| 요구사항 | 내용 |
|---|---|
| 카테고리 | 전체 / 몸 / 행동 / 생태 / 사람과의 관계 |
| 카드 구성 | 질문(제목), 요약 2줄, 카테고리 배지 |
| 정렬 | 최신순 |
| 페이지네이션 | **1차 미적용** (30편 미만이므로 전체 표시) |
| 빈 상태 | 해당 카테고리에 글이 없으면 "곧 채워질 예정" 안내 |

---

### F-04. 콘텐츠 상세 (`/library/[category]/[slug]`)

**렌더링 방식**: SSG (신규 발행 시 재빌드)

| 순서 | 영역 | 요구사항 |
|---|---|---|
| 1 | 질문 (H1) | 페이지 `<title>`과 동일 |
| 2 | 본문 | 마크다운 렌더링. 3~5문단 |
| 3 | 논문 출처 | 저자·연도·제목·링크. **외부 링크는 `rel="noopener"`, 새 탭** |
| 4 | 관련 영상 | `video_id` 있을 때만 노출. 썸네일 클릭 시 iframe 로드 |
| 5 | 반응 | 반응 목록(등록 즉시 공개) + 작성 폼 |
| 6 | 다음 읽을거리 | 동일 카테고리 글 3건 |

**SEO 요구사항**

| 항목 | 값 |
|---|---|
| `<title>` | `{질문} - 비버마을` |
| `description` | `summary` 필드 |
| OG 이미지 | 영상 썸네일 또는 기본 이미지 |
| 구조화 데이터 | `FAQPage` (JSON-LD) |
| Canonical | 자기 자신 |

**성능 요구사항**
유튜브 iframe을 초기 로드하지 않음. **썸네일 이미지만 표시하고 클릭 시 iframe 삽입.**
사유: iframe 1개당 500KB 이상 로드되어 LCP를 직접 악화시킴.

### F-05. 오늘의 비버 (`/videos`)

**렌더링 방식**: ISR (`revalidate: 3600`)

| 요구사항 | 내용 |
|---|---|
| 목록 | 썸네일, 제목, 채널명, 게시일 |
| 정렬 | 게시일 최신순 |
| 개수 | 최근 30건 |
| 재생 | 썸네일 클릭 시 인페이지 iframe 삽입 |
| 반응 | 영상별 익명 반응 작성 가능 |

### F-06. 마을회관 (`/guestbook`)

| 요구사항 | 내용 |
|---|---|
| 작성 | 이름·인증 없음. 본문만 입력 |
| 글자 수 | **최대 30자.** 실시간 카운터 표시 (`12/30`) |
| 제출 조건 | 1자 이상, 30자 이하, 공백만 입력 불가 |
| 제출 후 | "등록됐어요!" 안내, 목록에 즉시 노출 (2026-08-21: 관리자 승인 절차 폐지 — `docs/결정사항.md` 참고) |
| 표시 | 등록된 것 전부, 최신순 |
| 레이트 리밋 | IP 기준 **1분 3건** |
| 도배 방지 | 동일 내용 10분 내 반복 차단, 일일 총량 500건 |
| 링크 정책 | 허용 도메인 외 링크 포함 시 제출 거부 |

**허용 도메인**: `instagram.com`, `youtube.com`, `youtu.be`

**에러 표시 규칙**
모든 검증 실패는 **입력 필드 바로 아래 인라인 텍스트**로 표시. 알럿·토스트 미사용.

## 6. 기능 요구사항 명세

### FR-01. 검색

| 항목 | 내용 |
|---|---|
| 설명 | 방문자가 입력한 키워드로 콘텐츠를 검색 |
| 입력 | 검색어 문자열 (1~100자) |
| 처리 | `question`, `content`에 대해 `ilike '%{q}%'` |
| 출력 | 일치 콘텐츠 목록 |

**수용 기준**
- [ ] "이빨" 입력 시 이빨 관련 콘텐츠가 노출됨
- [ ] 공백만 입력 시 검색이 실행되지 않고 인라인 안내가 표시됨
- [ ] 결과가 0건일 때 도서관 목록으로 가는 링크가 노출됨
- [ ] 특수문자(`%`, `_`) 입력 시 오류 없이 처리됨

---

### FR-02. 익명 반응 작성

| 항목 | 내용 |
|---|---|
| 설명 | 로그인 없이 30자 이하 반응을 작성 |
| 입력 | `target_type`, `target_id`, `content` |
| 처리 | 검증 → 레이트 리밋 → 도배 방지 확인 → 저장 후 즉시 공개 |
| 출력 | 성공 안내 메시지 |

**수용 기준**
- [ ] 30자 초과 입력이 불가능함 (입력 자체가 막힘)
- [ ] 공백만 입력 시 제출 버튼이 동작하지 않고 인라인 오류가 표시됨
- [ ] 제출 직후 목록에 바로 노출됨 (2026-08-21: 승인 절차 폐지)
- [ ] 1분 내 4번째 제출 시 거부되고 안내가 표시됨
- [ ] 같은 내용을 10분 내 다시 제출하면 거부되고 안내가 표시됨
- [ ] 허용되지 않은 도메인 링크 포함 시 거부됨
- [ ] 금칙어 포함 시 거부됨
- [ ] DB 제약(`char_length <= 30`)이 클라이언트 우회 시에도 동작함

---

### FR-03. 영상 자동 수집

| 항목 | 내용 |
|---|---|
| 설명 | 큐레이션 채널의 신규 영상을 매일 수집 |
| 실행 | Vercel Cron, 매일 09:00 KST |
| 처리 | 채널별 `playlistItems.list` → 신규만 `upsert` |
| 출력 | `videos` 테이블 갱신 |

**수용 기준**
- [ ] 동일 영상이 중복 저장되지 않음 (`youtube_id` unique)
- [ ] API 호출 실패 시에도 기존 데이터가 유지됨
- [ ] Cron 엔드포인트가 외부에서 임의 호출되지 않음 (시크릿 검증)
- [ ] 채널 1개 실패가 전체 수집을 중단시키지 않음

---

### FR-04. 방문자 카운터

| 항목 | 내용 |
|---|---|
| 설명 | 누적 방문자 수 표시 |
| 처리 | 대문 진입 시 증가. **동일 세션 중복 집계 제외** |
| 중복 방지 | `sessionStorage` 플래그 사용 |

**수용 기준**
- [ ] 새로고침 반복 시 숫자가 증가하지 않음
- [ ] 새 세션에서는 증가함
- [ ] 조회 실패 시 화면 전체가 깨지지 않음

**주의**
`sessionStorage` 기반이므로 정확한 집계가 아님. **연출 요소로 정의하며 지표로 사용하지 않음.**

---

### FR-05. 커서 추적 비버

| 항목 | 내용 |
|---|---|
| 설명 | 마우스를 따라 비버 이미지가 이동 |
| 구현 | `requestAnimationFrame` + 선형 보간 (계수 0.1) |
| 조건 | 포인터가 마우스인 환경에서만 활성화 |

**수용 기준**
- [ ] 모바일·터치 환경에서 렌더링되지 않음
- [ ] `prefers-reduced-motion: reduce` 설정 시 비활성화됨
- [ ] 클릭 등 페이지 상호작용을 방해하지 않음 (`pointer-events: none`)

## 7. API 명세 (Next.js Route Handler)

| 메서드 | 경로 | 설명 | 인증 |
|---|---|---|---|
| GET | `/api/search?q=` | 콘텐츠 검색 | 없음 |
| POST | `/api/comments` | 반응 작성 | 없음 (레이트 리밋) |
| GET | `/api/visitors` | 방문자 수 조회 | 없음 |
| POST | `/api/visitors` | 방문자 수 증가 | 없음 (세션 검증) |
| GET | `/api/cron/videos` | 영상 수집 | **시크릿 헤더 검증** |

### 응답 규격

```ts
// 성공
{ ok: true, data: T }

// 실패
{ ok: false, error: { code: string, message: string } }
```

### 에러 코드

| 코드 | 상황 | HTTP |
|---|---|---|
| `INVALID_INPUT` | 검증 실패 | 400 |
| `RATE_LIMITED` | 레이트 리밋 초과 | 429 |
| `FORBIDDEN_DOMAIN` | 허용되지 않은 링크 | 400 |
| `UNAUTHORIZED` | Cron 시크릿 불일치 | 401 |
| `INTERNAL_ERROR` | 서버 오류 | 500 |

**원칙**
에러 메시지는 사용자에게 그대로 노출되므로 **기술 용어 없이 작성**할 것.
예: "잠시 후 다시 시도해 주세요" (O) / "500 Internal Server Error" (X)

## 8. 데이터 유효성 규칙

| 필드 | 규칙 | 검증 위치 |
|---|---|---|
| `comments.content` | 1~30자, 공백만 불가 | 클라이언트 + 서버 + DB |
| `comments.content` 링크 | 허용 도메인만 | 서버 |
| `articles.slug` | 소문자 영문·숫자·하이픈만 | 서버 |
| `articles.category` | 4개 값 중 하나 | DB (`check` 제약) |
| 검색어 | 1~100자 | 클라이언트 + 서버 |

**3중 검증 원칙**
클라이언트 검증은 UX용, 서버 검증은 보안용, DB 제약은 최종 방어선.
**클라이언트 검증만으로 처리하는 항목을 두지 않음.**

## 9. 공통 상태 정의

모든 목록·상세 화면은 아래 4가지 상태를 반드시 구현함.

| 상태 | 처리 |
|---|---|
| 로딩 | 스켈레톤 UI. 스피너 미사용 (레이아웃 흔들림 방지) |
| 정상 | 콘텐츠 표시 |
| 빈 상태 | 안내 문구 + 다음 행동 링크. **막다른 길 금지** |
| 에러 | "잠시 후 다시 시도해 주세요" + 재시도 버튼 |

## 10. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 유튜브 영상이 삭제됨 | iframe 오류 시 "영상을 불러올 수 없어요" 표시. 페이지는 정상 |
| 논문 링크가 만료됨 | 링크는 유지. 저자·연도 정보로 검색 가능하도록 병기 |
| 동일 IP 대량 반응 작성 | 레이트 리밋으로 차단. 429 응답 |
| 30자 초과를 API 직접 호출로 시도 | 서버 검증 + DB 제약으로 이중 차단 |
| 존재하지 않는 slug 접근 | 404 페이지. 도서관 목록 링크 포함 |
| 카테고리 오타 URL | 404 처리 |
| 자바스크립트 비활성 | 콘텐츠 열람은 정상 (SSG). 검색·반응은 미동작 |
| Supabase 무료 티어 일시정지 | Cron이 매일 동작하므로 해당 없음 |
