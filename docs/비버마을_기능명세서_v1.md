# 비버마을 — 기능 명세서

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-08-19 |
| 대상 범위 | 1차 (마을 개장) |
| 상위 문서 | 비버마을 기획서 v1.1, PRD v1.0 |

> **노션 활용 안내**
> 3장 기능 목록 표는 노션 **데이터베이스**로 붙여넣으면 상태·담당·우선순위 필터링이 가능함.
> 4장 상세 명세는 각 기능을 **하위 페이지**로 분리하면 관리가 편함.

---

## 1. 기능 분류 체계

```
비버마을
├─ A. 콘텐츠      도서관 글 조회·탐색
├─ B. 검색        키워드 검색
├─ C. 영상        유튜브 수집·노출
├─ D. 반응        익명 코멘트
├─ E. 연출        커서 비버, 방문자 카운터
└─ F. 시스템      Cron, 에러 처리, SEO
```

**기능 ID 규칙**: `{분류}-{일련번호}` (예: `A-01`)

---

## 2. 권한 정의

| 권한 | 대상 | 설명 |
|---|---|---|
| `PUBLIC` | 모든 방문자 | 로그인 없이 접근 |
| `ADMIN` | 운영자 | Supabase 대시보드 직접 접근 (1차 기준) |
| `SYSTEM` | 서버·Cron | 서비스 키 사용, 외부 호출 불가 |

## 4. 기능별 상세 명세

### A-01. 콘텐츠 상세 조회

| 항목 | 내용 |
|---|---|
| **경로** | `/library/[category]/[slug]` |
| **렌더링** | SSG |
| **권한** | PUBLIC |
| **입력** | `category`, `slug` (URL 파라미터) |
| **처리** | `articles`에서 `slug` 일치 및 `published = true`인 1건 조회 → 마크다운 렌더링 → 관련 영상·반응·추천글 병렬 조회 |
| **출력** | 질문, 본문, 논문 출처, 영상, 반응 목록, 추천글 3건 |
| **예외** | 미존재 slug → 404 / `published = false` → 404 |

**표시 순서**
질문(H1) → 본문 → 논문 출처 → 관련 영상 → 반응 → 다음 읽을거리

---

### A-02. 도서관 목록 조회

| 항목 | 내용 |
|---|---|
| **경로** | `/library` |
| **렌더링** | SSG |
| **권한** | PUBLIC |
| **입력** | 없음 |
| **처리** | `published = true`인 전체 콘텐츠를 `created_at` 내림차순 조회 |
| **출력** | 카드 목록 (질문, 요약 2줄, 카테고리 배지) |
| **예외** | 결과 0건 → "곧 채워질 예정" 안내 표시 |

**비고**
1차에서는 페이지네이션 미적용 (30편 미만 전제).

### B-01. 키워드 검색

| 항목 | 내용 |
|---|---|
| **경로** | `/search?q=`, `GET /api/search` |
| **렌더링** | CSR (`noindex`) |
| **권한** | PUBLIC |
| **입력** | 검색어 (1~100자) |
| **처리** | `question` 또는 `content`에 `ilike '%{q}%'` 적용 → 질문 일치 우선 정렬 |
| **출력** | 콘텐츠 목록 |
| **예외** | 공백만 입력 → 미실행 + 인라인 안내 / 100자 초과 → 절삭 / 결과 0건 → B-03 처리 |

**보안**
검색어의 `%`, `_`는 이스케이프 처리하여 의도치 않은 패턴 매칭을 방지함.

| 항목 | 내용 |
|---|---|
| **권한** | PUBLIC |

**문구**: "아직 그 답은 준비 중이에요. 다른 궁금증은 어떠세요?"

**원칙**

### C-02. 지연 재생

| 항목 | 내용 |
|---|---|
| **권한** | PUBLIC |
| **입력** | `youtube_id` |
| **처리** | 초기에는 썸네일 이미지만 렌더링 → 클릭 시 iframe DOM 삽입 |

### C-03. 영상 자동 수집

| 항목 | 내용 |
|---|---|
| **경로** | `GET /api/cron/videos` |
| **권한** | SYSTEM |
| **실행** | Vercel Cron, 매일 09:00 KST |
| **입력** | 시크릿 헤더 |
| **처리** | 채널 목록 순회 → `playlistItems.list` 호출 → `youtube_id` 기준 `upsert` |
| **출력** | 수집 건수 |
| **예외** | 시크릿 불일치 → 401 / 개별 채널 실패 → 로그 후 다음 채널 계속 / 전체 실패 → 기존 데이터 유지 |

**중요**
채널 1개의 실패가 전체 수집을 중단시키지 않도록 `try-catch`를 **채널 단위로** 적용함.

### D-01. 반응 작성

| 항목 | 내용 |
|---|---|
| **경로** | `POST /api/comments` |
| **권한** | PUBLIC |
| **입력** | `target_type`, `target_id`, `content` |
| **처리** | D-03 검증 → D-04 레이트 리밋 확인 → D-05 도배 방지 확인 → 저장 후 즉시 공개 |
| **출력** | 성공 안내 메시지 |
| **예외** | 검증 실패 → 400 / 리밋 초과 → 429 / 중복 내용 → 409 / 일일 총량 초과 → 503 |

**저장 후 동작 (2026-08-21 변경)**
등록된 반응은 관리자 승인 없이 즉시 노출됨 — 원래 기획 의도("누구나 와서 댓글 달고
공감할 수 있는")가 열린 반응이었는데, 아래 옛 D-05(승인 후 공개)가 이와 어긋나 있어서
바로잡음. 도배는 승인 절차 대신 D-04(레이트 리밋) + D-05(아래, 도배 방지)로 막는다.
문구: "등록됐어요!"

### D-03. 입력 검증

| 검증 항목 | 규칙 | 실패 시 |
|---|---|---|
| 최소 길이 | 1자 이상 | `INVALID_INPUT` |
| 최대 길이 | 30자 이하 | `INVALID_INPUT` |
| 공백 검사 | 공백만 입력 불가 | `INVALID_INPUT` |
| 링크 도메인 | 허용 목록만 | `FORBIDDEN_DOMAIN` |
| 금칙어 | 욕설·스팸 키워드 목록에 없어야 함 | `BANNED_KEYWORD` |

**허용 도메인**: `instagram.com`, `youtube.com`, `youtu.be`

**3중 검증**

| 계층 | 목적 |
|---|---|
| 클라이언트 | 즉각적 피드백 (UX) |
| 서버 | 우회 차단 (보안) |
| DB `check` 제약 | 최종 방어선 |

클라이언트 검증만으로 처리하는 항목을 두지 않음.

### D-05. 도배 방지 (2026-08-21, 옛 "반응 승인" 대체)

관리자 승인 절차 없이 등록 즉시 공개하는 대신, 아래 두 장치로 도배를 막는다.

| 항목 | 내용 |
|---|---|
| **권한** | SYSTEM |
| **동일 내용 반복 차단** | 같은 IP가 같은 대상(target_type + target_id)에 같은 내용을 10분 안에 다시 올리면 거부(`DUPLICATE_CONTENT`, 409) |
| **일일 총량 제한** | 사이트 전체 하루 등록 500건 초과 시 거부(`DAILY_LIMIT_REACHED`, 503) — IP를 바꿔가며 도배하는 경우의 최후 안전장치 |

**비고**
관리자 승인 화면은 만들지 않음(원래 계획대로 별도 관리자 화면 없음). 대신 필요하면
Supabase 대시보드에서 `comments` 테이블 행을 직접 삭제하는 방식으로 사후 대응한다.

### E-02. 방문자 카운터

| 항목 | 내용 |
|---|---|
| **경로** | `GET/POST /api/visitors` |
| **권한** | PUBLIC |
| **처리** | 대문 진입 시 `sessionStorage` 플래그 확인 → 없으면 증가 후 플래그 설정 |
| **출력** | 누적 방문자 수 (`toLocaleString()` 적용) |
| **예외** | 조회 실패 → 카운터 영역만 숨김. 페이지는 정상 렌더링 |

**정의**
`sessionStorage` 기반이므로 정확한 통계가 아님. **연출 요소로 정의하며 성과 지표로 사용하지 않음.**

|---|---|---|
| 미존재 페이지 | 404 | 안내 + 도서관 목록 링크 |
| 서버 오류 | 500 | "잠시 후 다시 시도해 주세요" + 재시도 버튼 |
| API 검증 실패 | 400 | 인라인 오류 텍스트 |
| 레이트 리밋 | 429 | 인라인 안내 |

**원칙**
에러 메시지에 기술 용어를 노출하지 않음. 알럿·토스트 대신 **인라인 표시**를 사용함.

## 7. API 응답 규격

```ts
// 성공
{ ok: true, data: T }

// 실패
{ ok: false, error: { code: string, message: string } }
```

| 코드 | 상황 | HTTP |
|---|---|---|
| `INVALID_INPUT` | 검증 실패 | 400 |
| `FORBIDDEN_DOMAIN` | 허용되지 않은 링크 | 400 |
| `UNAUTHORIZED` | Cron 시크릿 불일치 | 401 |
| `NOT_FOUND` | 리소스 없음 | 404 |
| `RATE_LIMITED` | 리밋 초과 | 429 |
| `INTERNAL_ERROR` | 서버 오류 | 500 |
